# 正式网页版部署指南

当前项目适合拆成两个服务上线：

- 前端：`frontend/`，React + Vite，部署到 Vercel 或 Netlify。
- 后端：`api_server.py`，Python API，部署到 Render / Railway / Fly.io / 云服务器。

这种方式比 Streamlit 更像正式网站：用户打开的是前端网址，前端再请求后端 API。DeepSeek API Key 只放在后端平台环境变量里，不放进前端代码，也不要提交到 GitHub。

## 1. 先上传到 GitHub

在项目根目录执行：

```bash
git init
git add .
git commit -m "Prepare web deployment"
git branch -M main
git remote add origin https://github.com/你的用户名/你的仓库名.git
git push -u origin main
```

确认不要提交这些内容：

- `.venv/`
- `frontend/node_modules/`
- `frontend/dist/`
- `.streamlit/secrets.toml`
- `runtime/`
- `reports/`

项目里的 `.gitignore` 已经排除了这些目录和敏感文件。

## 2. 部署后端到 Render

Render 配置：

- Service type：Web Service
- Repository：选择刚刚上传的 GitHub 仓库
- Root Directory：留空，也就是项目根目录
- Runtime：Python
- Build Command：`pip install -r requirements.txt`
- Start Command：`python api_server.py`
- Health Check Path：`/api/health`

环境变量：

```text
DEEPSEEK_API_KEY=你的 DeepSeek API Key
SHENZHI_RUNTIME_DIR=/opt/render/project/src/runtime
```

后端代码已经支持 Render/Railway 常用的 `PORT` 环境变量；如果平台提供了 `PORT`，服务会自动监听 `0.0.0.0:$PORT`。本地运行仍默认是 `127.0.0.1:8765`。

Render 部署完成后，打开：

```text
https://你的后端域名.onrender.com/api/health
```

如果看到类似下面的返回，就说明后端通了：

```json
{"status":"ok"}
```

注意：如果不配置持久化磁盘，Render 的运行文件系统在重启或重新部署后可能丢失运行时写入的数据。当前问诊历史存在 SQLite 运行目录里；演示可以先用默认方式，正式长期使用建议给 Render 服务挂 Persistent Disk，然后把 `SHENZHI_RUNTIME_DIR` 指到磁盘挂载目录。

## 3. 部署前端到 Vercel

Vercel 配置：

- Import Project：选择同一个 GitHub 仓库
- Framework Preset：Vite
- Root Directory：`frontend`
- Build Command：`pnpm build`
- Output Directory：`dist`

环境变量：

```text
VITE_API_BASE_URL=https://你的后端域名.onrender.com
```

保存后重新部署前端。Vite 会在构建时把 `VITE_API_BASE_URL` 写入前端包，所以改环境变量后需要触发一次新部署。

## 4. 或者部署前端到 Netlify

Netlify 配置：

- Base directory：`frontend`
- Build command：`pnpm build`
- Publish directory：`dist`

环境变量同样设置：

```text
VITE_API_BASE_URL=https://你的后端域名.onrender.com
```

## 5. 上线后验证

按这个顺序检查：

1. 打开后端 `/api/health`，确认返回 `{"status":"ok"}`。
2. 打开前端网址，确认页面能加载。
3. 新建一次问诊，发送一句问题，确认患者 Agent 能回复。
4. 点导出问诊记录，确认下载的是 PDF。
5. 打开浏览器开发者工具 Network，确认 `/api/chats` 请求发往后端域名，而不是 Vercel/Netlify 自己的域名。

## 6. 公开分享前的安全提醒

当前登录界面主要是 UI 状态，不是严格的后端账号权限系统。只要别人知道前端地址，就可能调用后端接口并消耗你的 DeepSeek API Key。公开分享前建议至少做其中一种：

- 加一个后端访问密码或真实登录鉴权。
- 在后端限制 CORS，只允许你的前端域名访问。
- 使用平台的访问控制、Basic Auth 或反向代理保护。
- 只把链接发给小范围测试用户。

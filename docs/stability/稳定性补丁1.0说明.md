# 神志思训稳定性补丁 1.0

## 已加入的稳定性能力

1. 问诊会话自动保存到本地 SQLite 数据库。
2. 页面刷新、浏览器断线或网络波动后，重新打开网页可恢复最近会话。
3. 模型请求失败时自动进行有限次数重试。
4. 患者回答生成失败时，不会把错误提示写入问诊记录。
5. 失败的问题会保留在页面中，可点击“重新生成患者回答”。
6. 长对话默认只渲染最近 16 轮，可点击“加载更早记录”继续查看。
7. 模型调用耗时、失败原因、会话恢复和关键操作会写入运行日志。

## 运行时文件

程序首次运行后，会自动创建：

```text
runtime/
├── shenzhi_sessions.db
└── shenzhi_app.log
```

- `shenzhi_sessions.db`：保存本机问诊会话、督导反馈、评分和 SOAP。
- `shenzhi_app.log`：记录模型请求耗时与失败原因，便于排查问题。

`runtime/` 已加入 `.gitignore`，不会上传到 GitHub。

## 建议测试

1. 正常完成几轮问诊，刷新浏览器，确认对话仍然存在。
2. 临时断开网络，再恢复网络，确认可重新生成失败的患者回答。
3. 连续问诊超过 16 轮，确认聊天窗顶部出现“加载更早记录”。
4. 遇到调用异常时，查看 `runtime/shenzhi_app.log`。

## 当前适用范围

SQLite 方案适合本地演示和单机教学试用。后续多人同时使用时，建议迁移为独立后端服务和 PostgreSQL 数据库。
